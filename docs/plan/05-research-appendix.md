# 05. 리서치 부록 — 근거 자료

> 이 문서는 00~04·06~07 문서의 결론에 대한 **"왜 그런가"** 를 뒷받침하는 근거·수치·출처 모음이며, 전 문서의 **각주 역할**을 한다. 다른 문서에서 이미 확정된 결론(집행 스펙 = 02, 안전장치 파라미터 = 03, 모듈 구조 = 01, 실시간·감시 = 06, 자가 개선 = 07)은 반복하지 않고, 그 결론이 나온 근거만 기술한다.
>
> 조사 시점은 **2026년 7월**이다.

## 0. 근거 등급 표기 규칙

이 문서의 모든 주장에는 아래 등급이 붙는다. **등급이 없는 문장은 근거가 없다는 뜻이 아니라, 해당 단락 첫머리의 등급을 상속한다는 뜻이다.**

| 등급 | 의미 | 이 문서에서의 취급 |
|---|---|---|
| **확인** | 1차 소스(공식 문서·공식 레포 소스코드·법령)에서 직접 확인 | 설계 근거로 즉시 사용 가능 |
| **높음** | 복수의 신뢰 가능한 소스가 일치. 단 실호출·실측 검증은 없음 | 설계 근거로 사용하되 M1에서 확인 |
| **중** | 2차 출처·커뮤니티 실측 기반. 상호 모순 없음 | 폴백 경로를 함께 설계 |
| **추론** | **확인된 사실들의 연역** — 새 사실을 주장하지 않는다(예: hard 필터 강도 × 상폐 사유 분포 → base rate) | 설계 근거로 사용 가능하되 **전제가 바뀌면 결론도 바뀐다**는 것을 명시한다. 새 사실을 주장하는 순간 **추측**으로 강등 |
| **추측** | 이론적 추론 또는 우리 자체 합성. 논문·문서에 없음 | **검증 전 채택 금지**. 반드시 실험 항목으로 등록 |
| **재확인 필요** | 접근 제한(egress 차단·인증 필요)으로 확인 못 함 | M1 스파이크 대상. §11에 총괄 |

**조사 환경 제약(정직성)**: 조사 세션의 egress 정책이 `openapi.krx.co.kr`, `opendart.fss.or.kr`, `kind.krx.co.kr`, `api-manager.upbit.com`, `nasdaqtrader.com`, `sec.gov`, `new.real.download.dws.co.kr`, KIS Developers 포털 접속을 403으로 차단했다. **엔드포인트를 직접 호출해 응답을 확인한 항목은 하나도 없다.** KIS 관련 필드는 공식 GitHub 레포(`koreainvestment/open-trading-api`)를 클론해 소스에서 직접 확인한 것이므로 신뢰도가 높지만, **"필드가 문서·코드에 있다"와 "실계좌에서 값이 정확히 채워진다"는 다르다.** 이 구분을 흐리지 않기 위해 §7·§8·§9의 모든 KIS 항목에 등급을 개별 표기했다.

## 1. 참고 레포지토리 심층 분석

### 1.1 freqtrade (github.com/freqtrade/freqtrade, ~52.7k★)

**아키텍처**: `Worker`(상태머신 RUNNING/PAUSED/STOPPED/RELOAD_CONFIG + throttle 루프)가 `FreqtradeBot`(오케스트레이터)을 감싸고, `IStrategy`(pandas vectorized 시그널), `Exchange`(ccxt 추상화, dry-run 분기 내장), `persistence`(SQLAlchemy Trade/Order + 백테스트용 in-memory `LocalTrade`), `RPCManager`(Telegram/REST/Webhook 브로드캐스트)로 구성. 컴포넌트 로딩은 `resolvers/` 디렉토리의 Resolver 패턴(이름 기반 동적 로드).

**dry-run 분기 (가장 이식 가치 높은 패턴)**: `dry_run: true`면 봇/전략/persistence/RPC는 전부 동일 코드로 돌고, 분기는 Exchange 계층 최하단에만 존재 — `create_order()`가 `create_dry_run_order()`로 위임해 합성 주문을 로컬 dict에 저장, `fetch_order()`/`cancel_order()`도 같은 메서드 내에서 분기. 시장가는 실제 orderbook을 순회해 체결가 산출(최대 5% 슬리피지 상한), 지정가는 가격 도달 시에만 체결. **낙관적 편향**: 지정가 무조건 체결(가격 도달 시), 시장가 슬리피지 상한 5% — 페이퍼 성과가 실거래보다 좋게 나오는 구조적 편향이 있음을 문서화해야 한다(01 §3.2 PaperExecutionEngine 설계에 반영).

**Protections 서킷브레이커**: `StoplossGuard`/`MaxDrawdown`/`CooldownPeriod` 등 독립 플러그인 체인, 설정 순서대로 평가. 03 §1 P1~P15의 직접 모델.

**상태머신 확장**: freqtrade의 상태 집합에는 "축소 운용" 상태가 없다 — RUNNING이거나 멈춘 상태뿐이다. 우리 설계는 여기에 **`SAFE_MODE`를 추가**했다(00 §5 원칙 10, 03 §3). 근거는 freqtrade가 아니라 §9.1~§9.2의 무인 운용 분석과 §6.3의 급락 국면 사례다: 단기매매 봇은 멈춰도 포지션이 대부분 현금이지만, **장기 자산배분 봇이 멈추면 "리밸런싱하지 않겠다"는 능동적 포지션을 취하는 것**이 되고 하락장에서는 그 자체가 리스크다. **참고 레포를 그대로 따르지 않은 몇 안 되는 지점이므로 명시해 둔다.**

**백테스팅**: 캔들 기반, 진입은 다음 캔들 open, stoploss를 ROI보다 먼저 평가(자본 보호 우선의 보수적 가정). `--timeframe-detail`로 캔들 내부 시뮬 보완. 별도 도구 `lookahead-analysis`(전체 vs 절단 dataframe 비교로 미래 참조 자동 탐지)와 `recursive-analysis` 제공 — 02 §8.3, 03 §4.5의 lookahead 자동탐지 도구의 원형. **hyperopt에는 walk-forward가 내장되어 있지 않다** — FreqAI 백테스트만 `train_period_days`/`backtest_period_days` 슬라이딩 윈도우 재학습을 지원. 우리 설계는 이 구멍을 skfolio의 WalkForward로 자체 보강(02 §8.2 게이트 C1).

**설정 계층화**: CLI > `FREQTRADE__` env 오버라이드 > 다중 config 파일 병합(공개/시크릿 분리) > 전략 기본값. `/reload_config`는 무중단 핫스왑이 아니라 **봇 객체 전체 재생성 + DB에서 포지션 복원**(01 §6.1, 03 §6.3의 배포 절차 모델).

**채택하지 않은 것**: 캔들 기반 단기매매 시뮬(장기 자산배분에는 일 단위 종가 리밸런싱 시뮬이 맞음 — 02 §8.1), hyperopt 파라미터 탐색(우리는 파라미터 탐색 자체를 최소화하는 철학 — 검증된 값을 config에 고정). **후자는 07 자가 개선 설계에서 다시 쟁점이 된다** — §10.6 및 [07 §7.1](07-self-improvement.md) 참조: 자가 개선 파이프라인이 "문헌 근거가 있는 특정 값 하나를 챌린저로 등록"하는 것을 넘어 대규모 탐색으로 번지면, 그것은 hyperopt를 재발명한 것이며 이 판단을 뒤집은 것이다.

### 1.2 OpenBB (github.com/OpenBB-finance/OpenBB, ~50k★)

**TET Fetcher 패턴**: 각 (데이터타입, 소스) 쌍을 `Fetcher[QueryParams, Data]`로 구현하고 `transform_query → extract_data → transform_data` 3단계를 강제. `extract_data`만 I/O를 하므로 캐싱·재시도·테스트 주입 지점이 명확 — 01 §3.3에서 그대로 이식.

**표준 모델 레지스트리**: `standard_models/`에 Pydantic 표준 스키마(`EquityHistorical` 등)를 두고 provider별 모델이 이를 상속. 논리 데이터타입 → Fetcher 매핑을 `fetcher_dict`로 선언적으로 관리해 "이 소스가 어떤 데이터를 제공하는가"가 코드로 자기문서화됨 — 01 §3.3 `ProviderRegistry`의 원형.

**시장 인지형 라우팅**: OpenBB 자체에는 없는 개선점으로 파악 — 심볼이 `.KS/.KQ`면 한국 provider, 미국 티커면 미국 provider로 라우팅하는 것은 우리가 추가하는 부분(01 §3.3 예시).

**한국 시장 공백**: 32개 provider 중 한국 소스(KRX/DART/KIS)는 전무. yfinance의 `.KS/.KQ` 티커는 있으나 비공식 스크레이핑 기반이라 프로덕션 부적합 — 우리는 KIS/FDR/pykrx 자체 Fetcher를 구현해야 한다(이미 01 §5, 02 §2.3에 반영). **§7.2가 이 판단을 더 강하게 뒷받침한다** — KIS 종목마스터 `.mst.zip`이 전종목 시장조치 플래그를 **인증 없이·rate limit 없이** 제공한다는 것을 발견했으므로, pykrx 의존도는 오히려 낮아진다.

**AGPL-3.0 주의**: 코드를 수정해 임베딩하면 소스 공개 의무 또는 상업 라이선스가 필요. **패턴만 자체 구현하고 코드는 복사하지 않는다** — 00 §4, 전 문서에 명시된 제약의 근거.

### 1.3 AI-Trader (github.com/HKUDS/AI-Trader)

**LLM 트레이딩 arena**: 6개 LLM(GPT/Claude/DeepSeek 등)이 실제 시장(미국/A주/크립토)에서 경쟁하는 벤치마크. **6개 모델 중 어느 것도 안정적으로 시장을 이기지 못했고, 순위가 시장·기간마다 뒤바뀜**(DeepSeek이 미국 +13%였지만 같은 시기 A주는 대부분 모델이 손실, 별개 크립토 대회에선 GPT-5가 −62.66%). 이 실증이 00 §4·01 §8·02 §서두의 "LLM은 의사결정자 금지" 원칙의 직접적 근거다.

**설계 패턴 이식**: MCP 기반 도구 분리 아키텍처(시세/검색/매매/계산을 독립 서비스로), 거래 규칙을 프롬프트가 아닌 **도구 레이어에서 코드로 강제**(종목 풀 소속·현금 잔고·lot 단위·T+1을 체결 자체가 불가능하게), look-ahead 방지 시점 필터링(발행일 정규화 + 시뮬레이션 날짜 이후 정보 차단), append-only JSONL 감사로그(결정+reasoning chain) — 01 §6.3 감사로그 설계의 원형. max_steps + STOP_SIGNAL + 지수 백오프의 런타임 가드레일 3종 세트.

**핵심 경고**: LLM 에이전트에 외부 데이터(검색 등)를 직접 물리면 prompt injection 공격면이 열림(TradeTrap 실증: 단일 컴포넌트 교란 → 포지션 폭주·대규모 낙폭). 리스크 관리는 LLM에 위임 불가(논문 스스로 "대부분 에이전트가 weak risk management") — 01 §7-8(보안 목록 8번 "Prompt injection 방어"), §8의 research 레이어 격리·import-linter 강제의 근거.

**이 경고가 확장 적용된 곳**: 00 §6.4의 **"감시 파이프라인 내 LLM 파싱 금지"** 하드 규칙이다. [R3]이 요구한 공지 파싱을 LLM에 맡기면, prompt injection이 **집행 경로(신규매수 금지·거래 동결)에 직결**된다. 감시 파서는 전부 결정론적 구조 파서(정규식 + Pydantic 스키마 검증)여야 하고, 자연어 요약이 필요하면 그것은 `research/` 레이어의 일이며 산출물은 사람이 읽는 리포트로만 흐른다(`surveillance -/-> research` import 금지).

**주의**: HKUDS/AI-Trader는 2026년 완전히 다른 플랫폼(v2)으로 재작성됨. 논문 세부 수치(arXiv:2512.10971) 일부는 2차 출처 교차 확인. **등급: 중.**

### 1.4 FinRobot (github.com/AI4Finance-Foundation/FinRobot)

**"숫자는 코드, 글은 LLM" 원칙**: 수익률·리밸런싱 수치·밸류에이션 등 모든 숫자는 순수 Python 연산으로 계산하고, LLM은 해석·코멘터리·리포트 작문만 담당. FinRobot 신버전조차 이 원칙으로 회귀했다는 점이 근거를 강화 — 01 §8의 `ReportNumbers.source = "computed_by_code_v1"` 및 `verify_numbers_unchanged()` 설계의 직접 근거.

**Data-CoT → Concept-CoT → Thesis-CoT 고정 파이프라인**: (1) 데이터 수집·정규화 (2) 해석(성과 요인 분해) (3) 종합 내러티브로 단계 고정. 자유형 GroupChat보다 고정 시퀀스가 재현성이 높다 — 01 §8 `build_monthly_report()`의 원형.

**확장 적용**: 07 자가 개선의 LLM 구조화 추출([07 §4.2~§4.3](07-self-improvement.md))에서 이 원칙이 **"숫자는 원문 인용, 판단은 사람"**으로 한 단계 더 강해진다. LLM이 논문에서 수치를 **재생성**하는 것을 금지하고, `quoted_numbers`의 각 수치가 **원문에서 추출한 수치 토큰 집합에 정확 일치**하는지 코드로 검증한다. 실패 수치는 삭제 + `UNVERIFIED_NUMBER` 플래그, 한 항목에서 2건 이상이면 항목을 강등한다([07 §4.3](07-self-improvement.md)이 정본).

**채택하지 않은 것**: 자유형 멀티에이전트 GroupChat(speaker selection 불안정·비용 급증 — 실전 예제도 대부분 2-agent 고정 nested chat), market forecaster의 "다음 주 등락 % 예측"(검증된 알파가 아니라 러프한 데모 — 국내 로보어드바이저에서 매매·자문 근거로 노출 시 투자권유 표현 규제 저촉 소지). 코어가 구버전 pyautogen 0.2.x에 고정 — 코드 재사용보다 패턴만 이식.

### 1.5 zipline (github.com/quantopian/zipline, 20k★) — 등급: 확인(레포 구조 직접 확인)

Quantopian의 이벤트 기반 백테스팅 엔진. **엔진 자체는 사실상 유지보수가 중단**되었고(`zipline-reloaded` 포크로 이어짐) 우리는 백테스터를 자체 구현하므로, 가치는 코드가 아니라 **설계 패턴 4개**에 있다.

| 패턴 | 우리 설계에 미친 영향 |
|---|---|
| **`BarData` 윈도우 접근자** — 전략에 전체 데이터프레임을 넘기지 않고 `current()`/`history(bar_count)`만 제공. 시뮬 시각 이후 인덱스가 **물리적으로 존재하지 않는다** | ★ **채택 — [02 §8.1 "데이터 접근 계약"](02-investment-engine.md)에 반영됨.** 우리 원안은 lookahead를 **사후 탐지**하는 방식이었는데, 이쪽이 더 강하다 — 접근 자체를 불가능하게 만든다. 탐지([02 §8.3](02-investment-engine.md))는 2차 방어선으로 유지 |
| **`asset_restrictions.py`** — "이 종목은 거래 불가"를 1급 추상으로. `HistoricalRestrictions`는 **효력 기간**을 가져 백테스트가 그 시점에 유효했던 제한을 적용한다 | ★ **부분 채택 — [02 §8.1.1 `sim_mode`](02-investment-engine.md)에 반영됨.** 정확히는 **두 층위로 나뉜다**: ⓐ **PIT 상태 플래그·유니버스 hard 필터의 as-of 재평가는 두 모드 모두에서 적용**한다(현재 플래그를 과거에 적용하는 것도 lookahead다) ⓑ **런타임 가드·SV 동결·SAFE_MODE 재생은 `sim_mode: with_guards`에서만** 한다 — `clean` 모드는 TE 5항목 분해 ③④의 기준선이어야 하므로 그것들이 없어야 한다 |

## 2. 대한민국 로보어드바이저 규제·세제 (2026년 7월 기준)

### 2.1 개인 자기계좌 API 자동매매의 법적 지위 — 등급: 높음

자본시장법상 투자일임업·투자자문업 규제는 "타인을 위한 영업행위"에 적용되므로 **본인 명의 계좌·본인 자금의 자동매매는 등록 대상이 아니다**(금지 규정 없음). 증권사들이 공식 Open API를 제공(KIS Developers, 키움 REST 등). 실무 제약은 법이 아니라 약관·기술 한도: 본인 명의 계좌만, 시세 데이터 재배포 금지. 허수성 호가·가장매매 등 불공정거래(시장질서 교란) 규정은 개인 알고리즘에도 그대로 적용 — 03 §1 P4(종목 쿨다운)·P11(회전율 일일 예산)의 근거.

**경계선**: 타인 계좌의 API 키를 받아 서버에서 주문을 실행하거나 자금을 모아 운용하고 대가를 받으면 **무등록 투자일임업**(형사처벌 대상, 자본시장법 위반). 불특정 다수 대상 유료 시그널 판매는 유사투자자문업 신고 필요, 1:1 맞춤 자문은 신고로도 불가(등록 필요). 이 근거로 00 §7, 03 부록의 "BYO-key 셀프호스팅만이 합법 경로" 원칙이 확정됨.

**파생 판정 — API 한도 우회 금지**: 커뮤니티에는 "KIS WebSocket 41건 한도를 복수 계좌·복수 앱키로 우회한다"는 패턴이 표준처럼 통용된다(§8.1). **타인 계좌를 동원하는 형태는 위 경계선을 넘으므로 본 시스템은 채택하지 않는다**(00 §6.4). 다행히 §8.2가 보이듯 한도는 실제로 병목이 아니다.

### 2.2 상용 RA 서비스 요건 (참고, 현재 범위 외) — 등급: 높음

투자자문업·투자일임업은 등록제. 일반투자자 대상 투자일임업 자기자본 요건 약 **15억원**, 전문인력(투자운용인력) 필요. **코스콤 로보어드바이저 테스트베드**: 사전 서류심사 → 6개월 실계좌 운용심사(알고리즘의 합리성·개인 맞춤성·분산 포트폴리오 요건) → 시스템심사(해킹·장애 대응), 총 약 7개월, 참가비 알고리즘당 약 50만원, 심사 연 4회. 통과 알고리즘은 ratestbed.kr에 성과 공시. 2019년부터 테스트베드 통과 RA로 **비대면 투자일임계약** 허용(비대면 일임 자기자본 요건이 15억으로 완화). 퇴직연금 RA 일임은 2024.12 규제샌드박스(혁신금융서비스)로 시작, 2025.3 최초 출시, IRP 한정·연 900만원 한도 — 03 부록 참조.

### 2.3 세제 (2026) — 등급: 높음

**금융투자소득세(금투세)**: 2024.12 시행 전 폐지 확정, 2026.7 현재 기존 체계 유지.

**해외주식 양도세**: 기본공제 연 250만원, 세율 22%(양도세 20%+지방세 2%), 이듬해 5.1~5.31 자진신고. 손익통산은 같은 과세연도 내 해외주식 간 + 과세대상 국내주식(대주주·비상장·장외) 간만 가능하며 **손실 이월공제는 불가**(02 §5.1의 하베스팅 설계가 이월 불가를 전제로 한 이유). 연말 절세 매도는 **결제일이 연내여야 인정**(미국주식 T+1 결제, 2024.5부터) — 02 §5.1의 D\*−2 마감 역산 로직의 근거.

**배당소득 분리과세 신설**(조특법 §104조의27 고배당기업 주식 배당소득 과세특례): 2025.12.02 국회 본회의 통과. **2026.1.1 이후 지급분부터 2028.12.31이 속하는 사업연도 귀속분까지 3년 한시.** 대상은 **배당성향 40% 이상, 또는 25% 이상이면서 전년 대비 배당 10% 이상 증가**한 고배당 상장법인이 지급하는 현금배당(해외주식 배당 제외). 세율은 **2,000만원 이하 14% / 2,000만~3억 20% / 3억~50억 25% / 50억 초과 30%**(지방소득세 별도)이며 종합과세 대신 선택 가능. **정부안의 최고세율 35%는 국회 심의에서 30%로 인하되었으므로 개편안 기준 수치를 인용하면 안 된다.**

> **★ ETF·펀드·리츠·투자목적회사(SPC) 등 집합투자기구를 통한 간접투자 배당은 대상에서 제외된다.** [02 §2.1·§2.2](02-investment-engine.md)의 유니버스는 전부 ETF이므로 **이 제도의 적용분은 0이다. 따라서 `tax.yaml`에 분리과세 분기·세율표를 만들지 않는다.** 개별주 위성을 도입하는 경우에만 재검토한다 — 항목 자체를 삭제하지 않는 이유는 그때 같은 조사를 반복하지 않기 위함이다.

**절세 계좌**: ISA(연 2,000만원 납입, 총 1억, 의무보유 3년, 비과세 200만원(서민형 400만원), 초과분 9.9% 분리과세, 금소세 신고자 가입 불가), 연금저축(세액공제 연 600만원, 연금계좌 합산 납입한도 연 1,800만원 — **납입한도와 공제한도 구분**이 02 §1.3 워터폴 설계의 근거), IRP(합산 900만 공제, **위험자산 70% 한도**, 적격 TDF 예외). **2025.12 개정세법에는 ISA 한도 확대가 포함되지 않았고, 국민성장·청년형 ISA는 2026.7 세제개편안과 국회 통과 후에야 확정**되므로 현재 문서는 확정 수치만 사용하고 미확정 항목은 `tax.yaml`에 선반영하지 않는다.

**세액공제의 크기 — 이 시스템 알파와의 비교**: 연금저축 600만원 공제는 소득구간에 따라 13.2~16.5%, 즉 **연 79~99만원의 확정 수익**이다. 이 시스템이 리밸런싱 방식 개선으로 추구하는 알파는 §4.5.1에서 차용한 **연 5~21bp**이며, 1억원 계좌 기준 5~21만원이다. **공제 한도 미소진 1회가 시스템 전체 알파를 두 자릿수 배 압도한다.** 00 §2.2-④와 등급표 T9(`waterfall_gap_check`, 11/1)가 "개입 0회"를 목표로 삼지 않고 이 확인 절차를 **의도적으로 강제 개입으로 남긴** 정량적 근거가 이것이다.

**ISA 비과세 한도와 리밸런싱 회전율의 상호작용(2026-07 추가)**: ISA의 비과세 한도는 **금액**(200/400만원)이지 비율이 아니다. 밴드를 좁혀 회전율을 올리면 리밸런싱으로 실현된 매매차익이 이 한도를 조기 소진하고, 초과분은 9.9% 분리과세가 된다. 밴드를 좁혀 얻는 추적 정밀도(수 bp)와 잃는 비과세 한도는 비교 대상이 아니다 — **02 §4.3에서 ISA만 집행 모드와 무관하게 7%p/35% 밴드를 유지하는 근거**다. 연금저축·IRP는 계좌 내 매매가 과세이연이라 이 문제가 없으므로 `AccountMode=AUTO`에서 5%p/25%로 좁혀도 된다.

**해외주식 환전·외환 규제**: 일반투자자의 해외상장 증권 매매는 **국내 투자중개업자 경유 의무**(자본시장법 시행령 §184①, 외국환거래규정 §7-33) — Interactive Brokers 등 해외 브로커 직접 계좌는 위반 소지. 00 §6.4 "해외 브로커 직접 연동 배제" 원칙의 근거. 통합증거금 제도(원화 예수금으로 해외주식 주문 → 결제일 자동환전, 야간환율 우선 환전 후 익영업일 오전 주간환율 재정산)는 대부분 증권사가 제공 — 02 §4.1 미국 집행의 환전 전제.

### 2.4 미국 PTP 원천징수 — 등급: 높음

미국 **PTP(Publicly Traded Partnership)** 종목은 IRS §1446(f)에 따라 **매도 대금 총액(gross proceeds, gain이 아니다)에 10% 원천징수**가 부과된다. 손익과 무관하게 매도금액의 10%가 사라지므로, 손실 상태에서 팔아도 10%를 더 잃는다.

- 코어 후보(VTI/VOO/BND/SCHD 등)는 PTP가 아니므로 **현 유니버스에는 노출이 없다.**
- 그러나 **위성 슬리브 확장이나 대체 페어 교체 시 사고가 가능**하다. 특히 원자재·MLP 계열 ETF에 PTP 구조가 흔하다.
- KIS 해외 `search_info`가 **`ptp_item_yn` / `ptp_item_trfx_exmt_yn` 필드를 제공**한다(§7.4) → 02 §2.3 유니버스 필터에 **`ptp_item_yn == 'N'`을 hard 조건으로 추가**했다. 필드가 실제로 채워지는지는 M1에서 확인(§11).

**이 항목은 기존 00~05 문서 어디에도 없던 공백이었다.** 발생 확률은 낮지만 발생 시 손실이 확정적이고, 방어 비용이 필터 한 줄이므로 채택 판단이 자명하다.

## 4. 로보어드바이저 핵심 알고리즘 — 실증 근거

### 4.1 Wealthfront/Betterment 방법론 (02 §3의 직접 모델) — 등급: 높음

**Wealthfront**: 기대수익 추정은 CAPM 균형수익률을 베이스라인으로, 금리·크레딧 스프레드 등 거시변수 기반 견해를 Black-Litterman과 Gordon Growth Model로 결합. "표본평균을 직접 쓰지 않고 균형수익률에서 출발"이 핵심. 리밸런싱은 시간 기반이 아닌 threshold 기반, 현금 유입을 언더웨이트 매수에 우선 사용.

**Betterment**: Black-Litterman 기반. glide path는 시뮬레이션 기반 도출 — 리스크 레벨×시평×수익 백분위 조합에서 최적 주식비중을 구한 뒤 평균 — 02 §3.5 glide path 방법론의 원형(우리는 단순 잔여기간 규칙으로 축소해 채택했다). **리밸런싱 정책**: (1) 반응적 — 현금흐름을 드리프트 감소에 우선 사용 (2) 능동적 — 부족 시 매도-매수. 기본 drift tolerance 3%(크립토 7%) — 02 §4.3 밴드 파라미터의 벤치마크.

### 4.2 MVO의 실무적 문제 — raw MVO 배제의 근거 — 등급: 확인(2차 소스 복수 일치 — 원문 PDF 직접 대조 미완)

고전 MPT/MVO는 입력 추정오차에 극도로 민감해 불안정하고 집중된 코너 솔루션을 생성(Michaud의 "estimation-error maximizer" 비판). **Chopra & Ziemba(1993)**: 확실성등가손실(CEL) 기여 비율이 **기대수익 : 분산 : 공분산 ≈ 11 : 2 : 1**(위험허용도 50 기준) — 즉 기대수익 추정오차가 **분산 오차의 약 11배, 공분산 오차의 약 20배 이상**이며, 분산 오차가 공분산 오차의 약 2배다. **배수는 위험허용도에 의존한다**(허용도가 높을수록 기대수익 항의 상대 비중이 커진다 — 구체 수치는 원문 표 대조 전까지 적지 않는다). **DeMiguel-Garlappi-Uppal(2009)**: **14개 최적화 모델 중 어느 것도 out-of-sample에서 1/N 균등가중을 일관되게 이기지 못했다.** → 02 §3.1 "표본평균 기대수익은 코드 경로 자체가 없다"는 설계 결정의 학술적 근거.

> **정정 이력**: 이전 판본은 "기대수익 추정오차 = 공분산 오차의 약 2배"로 적어 **공분산 추정오차의 상대 위험을 10배 이상 과대평가**했다(11:2:1에서 별개 관계인 "분산 : 공분산 = 2 : 1"의 주어를 바꿔 옮긴 오류). 또 DGU 인용이 한국어 어순상 "1/N이 모델들을 이기지 못했다"는 **정반대 의미**로 읽혔다. 두 검증 모두 원문 PDF가 스캔 이미지라 직접 대조에 실패했으므로 절 제목의 등급을 "확인(학술 원문)"에서 낮췄다(§11 #17).

**이 원칙의 파생 적용(2026-07)**: §10.2에서 CVaR/EVaR/CDaR **목적함수**를 거부한 근거가 정확히 이것이다. 756 관측치 × 5% = **38개 관측치**가 5%-CVaR 전체를 결정하므로, CVaR 최소화는 raw MVO보다 **더 심한** 추정오차 증폭이다. "표본평균 금지"를 선언하고 "표본 꼬리에 직접 최적화"를 허용하는 것은 자기모순이다.

### 4.3 공분산 추정 — Ledoit-Wolf shrinkage — 등급: 확인(학술 원문)

**"Honey, I Shrunk the Sample Covariance Matrix"**: 표본 공분산과 구조화 타깃(상수상관/단일팩터/항등행렬)의 볼록결합. in-sample 편향을 감수하고 out-of-sample 분산을 줄이는 bias-variance 트레이드오프. 실증적으로 표본 공분산을 모든 시나리오에서 이기고, 자산 수 N≤225에서는 상수상관 타깃이 단일팩터보다 우수 — 02 §3.2 "상수상관 타깃" 선택의 직접 근거(우리 유니버스는 N≈8~12로 이 조건에 부합).

**용도 분리**: 공분산 추정기를 **두 개**로 나눈다.
- `Σ_strategic` = Ledoit-Wolf 상수상관, 756일, 월 1회 재추정 → **목표비중 산출 전용**(현행 유지)
- `Σ_monitor` = EWMA(λ=0.94, 60일) → **모니터링·서킷브레이커·리포팅 전용**

근거: EWMA는 위기 시 상관 급등을 빠르게 반영해 리스크 인지에 유리하지만, **목표비중 산출에 넣으면 변동성이 오를 때마다 목표가 흔들려** 사용자가 정확히 피하고 싶어 하는 "고빈도 목표 변경"이 된다. 두 추정기는 코드 경로가 다르며 `Σ_monitor`는 `engine/optimizer.py`에서 import 불가하게 구조로 강제한다. 신규 코드는 거의 없다 — 02 §7의 크립토 vol targeting이 이미 같은 EWMA(λ=0.94, 60일)를 쓴다.

### 4.4 전술 오버레이의 함정 — 위성 격리·앙상블 강제의 근거 — 등급: 높음

**듀얼 모멘텀(GEM)**: 원 백테스트는 1974~2011, 그러나 **2012년 이후 벤치마크 대비 지속 언더퍼폼**이 복수 소스에서 확인. ReSolve 분석: 룩백 기간·리밸런스 날짜 등 사양에 대한 민감성이 커서 단일 사양은 과최적화 위험이 높음 — 02 §6의 "룩백 {3,6,9,12}개월 앙상블 강제"의 직접 근거. **HMM 국면감지**: smoothed probability를 백테스트에 쓰면 lookahead bias로 성과가 과대평가됨 — 우리 설계에서 HMM 국면감지를 채택하지 않은 이유.

**Rebalance Timing Luck (Hoffstein-Faber-Braun)**: 같은 전략도 리밸런싱 **날짜**만 다르면 성과가 크게 갈린다. 이는 위성 슬리브의 단일 사양 백테스트 결과를 신뢰하지 않는 또 하나의 근거이며, 02 §6의 앙상블(복수 룩백 + 분산된 리밸런싱 시점) 요구를 강화한다.

### 4.5 리밸런싱 실증

#### 4.5.1 Vanguard 실증 — 무엇에 대해 참인가 — 등급: 확인

- **Jaconetti-Kinniry-Zilbering (2012, 60/40, 1926~)**: 월간/분기/연간 리밸런싱의 **위험조정수익은 사실상 무차별**. 월간이 연간 대비 약 **0.25%p/년의 추가 비용**을 발생시킨다. 연 1회는 일간 리밸런싱 수익의 **99%**를 10년당 거래 **250회 → 10회**로 달성한다.
- **Vanguard 2022 "Rational Rebalancing"**: 이를 **추적오차(비효용) vs 거래비용의 trade-off 최적화** 문제로 정식화.
- **Vanguard 2024-12 "The rebalancing edge"**: threshold 기반이 캘린더 기반 대비 연 **5~21bp** 우위. 월간 대비 적립기 **15~22bp**, 인출기 **22~25bp**, 거래비용은 월간의 **약 1/4**.

> **★ "이 시스템의 알파 추정 = 연 5~21bp"의 출처가 여기다.** 문서 세트 전반이 인용하는 그 숫자는 **독립적으로 산출한 추정이 아니라 위 Vanguard 실증치를 그대로 차용한 것**이며, 따라서 "임계 방식이 캘린더 방식 대비 얻는 우위"만을 뜻한다. 세제 최적화·집행 품질·감시가 기여하는 몫은 그 안에 포함되어 있지 않고, 반대로 한국 세제·정수 수량 제약으로 인한 열화도 반영되어 있지 않다. **자릿수 감각을 잡는 용도로만 쓰고, 성과 목표로 쓰지 않는다.**

**이 실증의 종속변수는 "목표비중 대비 드리프트를 언제 되돌리는가" 하나다.** 목적함수에 "보유 종목이 상장폐지 예정인가", "지금 호가창이 붕괴했는가"는 **변수로 존재하지 않는다.** 따라서 이 실증은 **리스크 이벤트 대응·집행 품질에 대해 아무 말도 하지 않는다** — 별개 문제다(§6).

**결정적 구분 — 감시 빈도 ≠ 거래 빈도**:

| | 감시(monitoring) 빈도 | 거래(trading) 빈도 |
|---|---|---|
| 캘린더 방식 | 낮음 (월/분기/연 1회) | 낮음 |
| **임계(threshold) 방식** | **높음 (일 단위)** | **낮음 (임계 돌파 시에만)** |
| 고빈도 리밸런싱 | 높음 | 높음 ← **이것만 해롭다** |

Vanguard가 "빈도를 높여도 개선 없다"고 말한 대상은 **거래 빈도**이고, 2024-12 연구가 "임계 방식이 캘린더를 이긴다"고 말한 것은 **감시 빈도가 높기 때문**이다. 00 §5 원칙 8("감시는 조밀하게, 목표 변경은 드물게")의 직접 근거다.

#### 4.5.2 Daryanani(2008) — 등급: 확인

이 논문의 주 논지는 부분 복귀 규칙이 아니라 관찰 빈도다:

> ***"rebalance less frequently, but look more frequently"*** — 리밸런싱은 덜 자주, 관찰은 더 자주.

정량 결과: **상대 밴드 20% + 5~10거래일 간격 관찰** → 무리밸런싱 대비 **+55bp/년**, 연 1회 리밸런싱 대비 **+30bp/년**. 이익의 원천은 자산군 간 산발적 드리프트에서 발생하는 buy-low/sell-high 기회이며, 자주 봐야만 포착된다.

**그런데 같은 논문이 일간 관찰(daily look)은 "profusion of small trades"로 역효과라고 명시하며 2주(5~10거래일) 간격을 최적으로 지목한다.**

**현 설계에 대한 판정**:

| 항목 | Daryanani 최적 | 현 설계 | 판정 |
|---|---|---|---|
| **look 빈도** | 5~10거래일 | **1거래일(07:30 일 1회) + 매시 `guard_monitor`** | **최적 구간 밖(더 조밀) — 늘릴 여지 없음** |
| 밴드 | 상대 20% | 상대 25% / 절대 5%p (Swedroe 5/25) | 정합 |
| 복귀 | 부분 복귀 | 50% 부분 복귀(§4.5.4에서 재검토 중) | 정합 |

> **전략적 리밸런싱 관점에서 이 프로젝트는 이미 최적 look 빈도를 넘어섰다. 일중 판정 추가는 Daryanani 기준으로도 순감점 영역이다.** 즉 [R2]를 "드리프트 판정을 더 자주"로 해석하는 것은 **어떤 실증으로도 지지되지 않는다.** 00 §2.2-① "일중 리밸런싱 판정 영구 금지"와 00 §6.2의 근거가 이것이다.
>
> **자기 면제를 피하는 정직한 표기(등급: 추론)**: 같은 논문이 경고하는 "daily look의 profusion of small trades"는 현 설계의 look 빈도(일 1회)에 **그대로 해당한다.** "이미 초과 달성"이라는 표현은 그 사실을 가리므로 쓰지 않는다. 우리가 그 역효과를 피한다고 보는 근거는 **상대 밴드 25% + 쿨다운 5거래일 + `T_min` 필터가 소액 거래를 상쇄한다**는 것이며 **실증이 아니라 추론**이다. [02 §8.2](02-investment-engine.md) EX-1의 `T_min` 스킵 비율·밴드 트리거 횟수 지표로 사후 검증한다.

#### 4.5.3 한국 세제 보정 — look 빈도를 늘릴 근거는 더 약하다 — 등급: 추론(방향은 확실)

Daryanani의 +30bp는 **1994~2005 · 미국 · 세전 · 5자산** 기준이다. 우리 환경은 다르다:

- 국내상장 해외 ETF 매매차익에 **배당소득세 15.4%** + 금융소득종합과세 합산(최고 49.5%)
- 해외상장 ETF 양도세 22%(공제 250만원 초과분)
- ISA 비과세 한도가 **금액 상한**이라 회전율이 한도를 조기 소진(§2.3)

즉 **한국에서는 회전율 증가의 비용이 미국 세전 기준보다 훨씬 크므로, look 빈도를 늘릴 근거가 오히려 더 약하다.**

> **정직성 표기**: 이 보정은 결론(look 빈도 증가 불필요)을 **강화하는 방향**이다. 즉 결론에 유리한 편향이 있을 수 있다는 것을 밝혀 둔다. 반대 방향의 증거(실시간 계층이 실제로 값을 하는 경우)는 §6.3·§6.5에 별도로 정리했다.

#### 4.5.4 부분 복귀 규칙 — 확정하지 않고 실험으로 넘긴다

**이론 — Davis-Norman(1990) 계보** (등급: 확인):
- 거래비용이 있으면 **거래하지 않는 것이 최적인 무거래 영역(no-trade region)**이 존재한다.
- Akian et al.(1996)이 다자산으로 확장 → 다차원 무거래 영역. 최근 연구는 비례 거래비용 하 무거래 영역이 **다차원 평행사변형**으로 닫힌 형태를 갖고 최적 정책을 **단일 QP 한 번으로** 계산 가능하다고 보고.
- **이론이 명시적으로 말하는 실무 원칙**:
  - 비용이 **비례적(proportional)**이면 → **영역 경계로 복귀. 절대 완전 복귀하지 않는다.**
  - 비용에 **고정(fixed) 요소**가 있으면 → 영역 **내부의 한 점**으로 복귀(오버슈트).
- **Leland**: 완전 복귀는 비최적 — 같은 결론.

**실증 — Vanguard 2024-12 "200/175"** (등급: 확인):
- TDF에서 임계 **200bp**, 목적지 **175bp**. 60/40에서 주식이 62%를 돌파하면 **61.75%로 복귀**하며 60%로 완전 복귀하지 않는다.
- 임계 200bp는 여러 예측모형에 걸쳐 견고했고, **목적지 175bp가 다른 목적지 대비 거래비용이 가장 낮았다.**
- 200/175 하에서 포트폴리오가 목표 대비 약 2%를 넘어 이탈한 적이 없었다.
- **이것이 Davis-Norman 이론의 실증적 확인이다** — 임계 200bp = 영역 경계, 목적지 175bp = 고정비용 때문에 경계에서 25bp 안쪽으로 오버슈트.

**현행 `부분 복귀 50%`의 두 가지 결함** (등급: 산술적 확인). 밴드 `b = 5%p` 기준:

| 드리프트 d | 현행 `0.5d`: 거래량 / 잔여드리프트 | destination `ρ·b`(ρ=0.875 → 4.375%p): 거래량 / 잔여드리프트 | 평가 |
|---|---|---|---|
| 5.5%p | 2.75 / **2.75** | **1.125** / 4.375 | 현행이 **2.4배 과다거래** |
| 6.0%p | 3.00 / 3.00 | 1.625 / 4.375 | 현행 과다거래 |
| 7.5%p | 3.75 / 3.75 | 3.125 / 4.375 | 유사 |
| 10.0%p | 5.00 / 5.00 | 5.625 / 4.375 | 유사 |
| 15.0%p | 7.50 / **7.50 (= 밴드의 1.5배!)** | 10.625 / 4.375 | **현행은 리밸런싱 후에도 밴드 1.5배 이탈 상태로 방치** |

1. **작은 돌파에서 과다거래** — 갓 밴드를 넘었을 뿐인데 드리프트의 절반을 거래한다. 비례비용 이론이 명시적으로 금지하는 행동.
2. **큰 돌파에서 위험통제 실패** — 15%p 이탈 시 리밸런싱을 하고도 7.5%p 이탈 상태로 남는다. 02 §4.3의 쿨다운 예외(드리프트 2×밴드 초과 시 쿨다운 무시)가 익일 재트리거로 부분 보완하지만, 이는 **여러 날에 걸친 반복 거래**를 만들어 비용을 더 쓴다.

**그런데 확정하지 않는다** (등급: 추측 — 반론이 실재한다):
- Vanguard 연구 대상은 **기관 TDF**다. 정수 제약 없음, 거래비용 극소, 세금 없음, 계좌 1개.

### 4.6 몬테카를로 설계 — block bootstrap 채택 근거 — 등급: 높음

parametric(정규/로그정규)은 fat tail을 과소평가하므로 Student-t 또는 bootstrap 병용 권장(복수 소스 일치). block bootstrap은 자기상관·변동성 군집을 보존 — 02 §9 "stationary block bootstrap 단일 엔진(평균 블록 6개월)" 채택의 근거(이중 엔진 병기는 비판 검증에서 과잉설계로 판정되어 제거, t-분포는 별도 스트레스 시나리오로 격하). **고정 인출 가정은 실패율을 30~50% 과대평가** — 02 §9의 Guyton-Klinger 가드레일 내장(마지막 불릿)의 근거.

**꼬리 시나리오 보강의 올바른 방법(2026-07)**: 꼬리위험을 최적화에 반영하려면 목적함수(CVaR)가 아니라 **시나리오 확장**이 통계적으로 훨씬 안전하다 — vine copula 합성데이터로 꼬리 시나리오를 보강한 뒤 그 위에서 기존 MVO를 돌린다. skfolio에 생성기가 내장되어 있다. **우선순위 낮음 — [02 §3.6](02-investment-engine.md)·[04 §4.4](04-roadmap.md)가 M10 이후로 분류한다**(02의 "M8+" 표기는 04의 일정 정본을 따른다). 근거는 §10.2.

### 4.7 파이썬 라이브러리 생태계 — skfolio 단일 채택 근거 — 등급: 높음

`skfolio`(BSD-3, 활발): scikit-learn 호환 API, Mean-Risk/Risk Budgeting/HRP/HERC 최적화, Ledoit-Wolf 등 공분산 추정기, **Walk-Forward/Combinatorial Purged CV 검증 도구 내장** — 최적화와 백테스트 검증을 한 프레임워크에서 처리 가능해 01 §1.5·02 §8.2에서 단일 채택.

**0.20.1 기준 제공 목록(2026-07 확인)**: 공분산 — Empirical, Gerber, Denoising, Detoning, EW, Regime-Adjusted EW, Ledoit-Wolf, OAS, Shrunk, Graphical Lasso CV, Implied. 최적화 — Mean-Risk, Risk Budgeting, HRP, HERC, NCO, **SchurComplementary**, **EntropyPooling**/OpinionPooling. 리스크척도 — Variance, CVaR, EVaR, MaxDrawdown, CDaR, Skew, Kurtosis 전부 선형계획 구현.
**없는 것**: Ledoit-Wolf **nonlinear shrinkage(QIS/GIS)** — 채택하려면 자체 구현이 필요하다(§10.1에서 거부).

`Riskfolio-Lib`(BSD-3)는 비판 검증에서 "이중화 과잉"으로 판정되어 배제. `vectorbt`는 Apache 2.0 + **Commons Clause**(판매 제한 비표준 조항)로 순수 오픈소스가 아니라 배제. `PyPortfolioOpt`는 개발 활동 둔화 추정으로 참고 구현으로만 활용.

**API 호환성은 재확인 필요**: 위 목록은 문서·PyPI 기준이며 실제 시그니처를 호출해 본 것은 아니다. 버전 고정 시점(M1)에 `MeanRisk`·`HierarchicalRiskParity`·`SchurComplementary`·`EntropyPooling`의 시그니처를 실측한다.

## 6. 실시간 이벤트 대응의 투자론적 타당성 (R-E) — [06 Part 1](06-realtime-and-surveillance.md)의 근거

**이 절이 [00 §2.2](00-overview.md)의 판정 규칙을 실제로 적용한 자리다.** 사용자 요구 [R2]("한도 내 최대 활용, 실시간 대응 강화")와 §4.5의 리밸런싱 실증이 충돌하는 것처럼 보였고, 그 충돌을 억지로 양립시키지 말라는 지시가 있었다. 결론부터: **충돌은 실재하지 않았고, 겹치는 영역에서는 실증이 이겼다.**

### 6.1 두 요구는 서로 다른 것을 말하고 있었다 — 등급: 확인(논리적 구분)

§4.5의 실증(Vanguard·Daryanani)이 대상으로 삼는 것은 **"리밸런싱을 판정하고 실행하는 빈도"**다. [R2]가 요구하는 것은 문언상 **"시장 상황에 대한 반응성"**이다. 이 둘이 같은 것이라는 가정이 충돌을 만들었다.

[00 §5](00-overview.md) 원칙 8이 이 구분을 네 축으로 고정한다.

| 축 | 현행 빈도 | §4.5 실증의 적용 대상인가 | [R2]로 늘릴 수 있는가 |
|---|---|---|---|
| ① 목표비중 산출 | 월 1회 | **예** — 늘릴 근거 없음 | 아니오 |
| ② 드리프트 밴드 판정 | 일 1회 | **예** — Daryanani의 최적 look 간격이 5~10거래일이므로 **현행이 이미 그보다 조밀하다** | 아니오 |
| ③ 가용성·리스크 이벤트 감시 | 일 1회 배치 | 아니오 — 실증의 대상 밖 | **예** |
| ④ 집행 품질(호가·NAV) | 집행 창 한정 | 아니오 — 실증의 대상 밖 | **예** |

**②에 대한 정직한 서술**: 우리는 이미 Daryanani가 최적이라 본 구간(5~10거래일)보다 **더 자주 보고 있다**. [R2]를 ②에 적용하면 "이미 과잉인 것을 더 늘리는" 방향이며, 이것이 [00 §2.2-①](00-overview.md)의 "일중 리밸런싱 판정 영구 금지"가 나온 자리다. 늘릴 여지가 있는 것은 ③④뿐이고, 그 둘은 알파가 아니라 **보험과 집행 품질**이다.

### 6.2 손절·드로다운 청산 — 등급: 확인(학술 원문)

Kaminski·Lo, *When Do Stop-Loss Rules Stop Losses?*: **랜덤워크(더 정확히는 독립증분) 하에서 단순 손절 규칙은 기대수익을 항상 감소시킨다.** stopping premium이 양(+)이 되는 것은 수익률에 양의 자기상관(모멘텀)이 있거나 레짐 전환이 존재할 때뿐이다.

함의 두 개가 우리 설계에 직접 반영되었다.

- 광범위 지수 ETF의 일간 수익률은 랜덤워크에 가깝다 → **코어 손절 금지**([02 §3.6](02-investment-engine.md)).
- 듀얼모멘텀 위성에 대해서는 **"조건 충족"이 아니라 "조건 충족이 전략의 가정에 근거한다"가 정확한 서술**이다 → **위성 슬리브의 DD 축소는 유지**([02 §6](02-investment-engine.md)).

> **여기서 논리 비약을 하지 않는다.** Kaminski-Lo의 조건은 **수익률 과정에 양의 자기상관이 실제로 존재하는가**이지 "전략이 그것을 가정하는가"가 아니다. §4.4가 기록한 GEM의 2012년 이후 지속 언더퍼폼은 오히려 반대 방향 증거다. **DD 축소를 유지하는 실질 근거는 이론 충족이 아니라 구조적 봉인 둘**이다 — ① 슬리브 상한 10%로 오류의 손실이 유한하게 묶인다 ② 롤링 3년 코어 대비 −5%p/년 하회 시 비활성화 권고. 검증은 위성 게이트 **S4에 "DD 축소 on/off A/B"**를 포함해 수행한다([02 §8.2](02-investment-engine.md)).

**이 분리가 이미 옳게 되어 있었다는 점이 중요하다.** [R2]를 반영하면서 코어에 DD 축소를 복사했다면 실증에 정면으로 반하는 변경이 되었을 것이다.

### 6.4 실시간 UI가 거래를 인과적으로 늘린다 — 등급: 확인(학술 원문)

- **Barber·Odean, *Trading Is Hazardous to Your Wealth*(JF 2000)**: 거래 회전율 상위 그룹이 하위 그룹 대비 연 **6.5%p** 낮은 순수익률. 총수익률 차이는 거의 없고 **차이는 전부 비용에서 나온다**.
- **Barber·Huang·Odean·Schwarz, *Attention-Induced Trading and Returns*(JF 2022)**: Robinhood 장애 기간에 **고주목 종목의 거래가 불균형적으로 감소**한 것을 이용해, 앱의 주목 유도 설계가 거래를 **인과적으로** 증폭시킴을 식별. 상관이 아니라 인과 식별이라는 점이 중요하다.

**이 시스템에서 가장 과소평가된 위험은 시스템 오류가 아니라 사용자의 과매매다.** 봇이 자동이어도 인간 개입 채널(`/reject`·`/pause`·파라미터 변경)이 존재하고, 실시간 화면은 그 채널의 사용 빈도를 높인다. → [03 §7.1](03-safety-operations.md)·[06 §4](06-realtime-and-surveillance.md)의 UI 격리 4규칙이 **선택이 아니라 필수 요건**인 이유.

특히 `look / breach / trade` 3분 계측이 없으면 **실시간 도입이 과매매로 새는지 사후 판정 자체가 불가능**하다 — 이것이 계측을 T0 착수와 동시에 구현하는 이유다.

| 항목 | 추정 | 산출 근거 |
|---|---|---|
| 실시간 호가 기반 marketable limit의 평균 슬리피지 절감 | **연 1~5bp** | 연간 회전율 추정 × 대형 ETF 스프레드(1~2틱) × 개선 가능 비율의 곱. **어느 항도 실측이 아니다** |
| 자릿수 비교용 기준값 | 연 5~21bp | **§4.5.1**(Vanguard 2024-12 실증치 차용 — **임계 방식이 캘린더 방식 대비 얻는 우위에 한정**). 00 §2.2를 출처로 적으면 00 → 05 → 00의 순환이 된다 |

**이 수치가 [06](06-realtime-and-surveillance.md)에서 가장 취약한 전제이며, 문서가 그렇게 명시하고 있다**([06 §14](06-realtime-and-surveillance.md)). 그래서 M9 진입 게이트를 ①(집행 품질 ≥5bp) 단독이 아니라 ②(게이트 판정 불일치율 ≥5%)와의 **OR**로 설계했다 — ①은 거의 확실히 탈락할 것으로 예상되기 때문이다.

**결론적으로 실시간의 정당화 근거는 평균 개선이 아니라 꼬리 차단이다**([00 §2.2-②](00-overview.md)). 무조건 채택되는 것은 ① 체결통보(이중 주문 방지) ② 업비트 24/7 가드 ③ 조건부 집행 게이트 셋뿐이며, 앞의 둘은 **REST 소비를 오히려 줄인다**.

## 7. 한국 시장 리스크 공시·시장조치 데이터 소스 (R-A) — [06 Part 2](06-realtime-and-surveillance.md)의 근거

### 7.1 KIS 공식 API가 이미 제공하는 필드 — 등급: **확인(공식 레포 소스코드)**

공식 레포 `koreainvestment/open-trading-api`를 클론해 소스에서 직접 확인했다. **[R3]이 요구하는 정보의 대부분은 스크래핑 대상이 아니라 이미 인증되어 있는 API의 1급 필드다.**

| TR / 파일 | 필드 | 커버 리스크 |
|---|---|---|
| `CTPF1002R` (주식기본조회) | `tr_stop_yn`(거래정지) · `admn_item_yn`(관리종목) · `etf_etn_ivst_heed_item_yn`(**ETF/ETN 투자유의종목**) · `lstg_abol_dt`(상장폐지일자) | KR-01·02·03·04 |
| `kospi_code.mst` / `kosdaq_code.mst` (종목마스터) | 거래정지 · 관리종목 · 시장경고 · 불성실공시 · 정리매매 플래그 | 전종목 스크리닝 |
| `ksdinfo_merger_split` / `ksdinfo_rev_split` / `ksdinfo_cap_dcrs` (예탁원) | `td_stop_dt`(매매거래정지일) | KR-12 사전 캘린더 |
| 해외 `search_info` | `ovrs_stck_tr_stop_dvsn_cd` · `lstg_abol_item_yn` · `ptp_item_yn` | US-01·02 + PTP 필터 |
| 업비트 `/v1/market/all?isDetails=true` | `market_warning`(유의종목) · `market_event.caution.*` | UP-01 |

**중요한 두 가지**

1. **마스터파일(`.mst.zip`)은 인증이 필요 없다.** 정적 파일 다운로드이므로 KIS REST rate limit 예산 밖이다.
2. **"필드가 코드에 있다"와 "실계좌에서 값이 정확히 채워진다"는 다르다.** egress 차단으로 실호출 확인을 못 했으므로 SP-A1·SP-A2를 M1 스파이크에 배치했다([06 §13.1](06-realtime-and-surveillance.md)).

> **[00 §6.3](00-overview.md)의 하드 규칙**: 공식 API가 있는 데이터의 스크래핑은 금지다. [R3]의 80%가 스크래핑 없이 해소되는 것은 설계 선택이 아니라 **원래 그랬던 것을 발견한 것**이다.

### 7.2 국내 ETF 상장폐지 통계 — 등급: 중(2차 출처, 상호 모순 없음)

| 연도 | 국내 ETF 상장폐지 건수 |
|---|---|
| 2023 | 14 |
| 2024 | **51** |
| 2025 | **50** |
| 2026 상반기 | 19 |

**급증은 사실이다. 그러나 우리 유니버스와 무관하다.** 주 사유가 **순자산 50억 미만**(관리종목 지정 요건) 및 **기초지수 상관계수 0.9 미만**인데, [02 §2.3](02-investment-engine.md)의 hard 필터(AUM ≥500억 · 상장 ≥3년 · 20일 거래대금 ≥10억)가 이 모집단을 사실상 전부 배제한다. 관리종목 기준 대비 **10배 마진**이다.

**이것이 [06 §5.3](06-realtime-and-surveillance.md)의 "base rate ≈ 연 0~1회" 판정의 근거이며, 그 판정이 감시 서브시스템을 27항목 → 7항목으로 줄인 근거다.** 판정 자체의 등급은 **추론**(필터 강도 × 상폐 사유 분포)이며 실측이 아니다.

### 7.3 ETF 투자유의종목 제도 — 등급: 높음

- **지정 기준**: 장 종료 시점 실시간 괴리율이 관리의무비율의 **2배**(국내물 6% / 해외물 12%) 이상으로 **3일 연속** → 지정예고 → 지정.
- **지정 효과**: **3매매일간 30분 단위 단일가매매**로 전환. 미해소 시 **매매거래정지**.

**설계 함의가 결정적이다**: 단일가 국면에서는 매도 집행 품질이 최악이 된다. **"감지 후 매도"가 가장 나쁜 선택이 되는 대표 사례**이며, [06 §8.1](06-realtime-and-surveillance.md)이 `ESC_LIQUIDATE`를 등급 enum 밖에 두고 A3 영구로 고정한 실증적 근거다.

### 7.4 거래정지·상장폐지 시 실제로 무엇이 가능한가 — 등급: 높음

| 상태 | 매수 | 매도 | 비고 |
|---|---|---|---|
| 매매거래정지 | 불가 | **불가** | "위험 감지 → 즉시 청산"은 **이미 실행 불가능**한 정책 |
| 개별주 상장폐지 확정 | 불가 | 정리매매 기간(≤7거래일, 30분 단일가)에만 | 코어가 ETF-only이므로 해당 없음 |
| **국내 ETF 상장폐지** | — | — | **정리매매 없이 해지상환** — 상폐일 NAV에서 비용을 뺀 금액이 계좌로 자동 입금 |

**세 번째 행이 [06 §8.2](06-realtime-and-surveillance.md)의 네 번째 함의를 만든다: "행동하지 않으면 자산을 잃는다"는 시나리오가 아니다.** 해지상환은 NAV 기준이라 괴리율 손실도 거래비용도 없다. 방치가 오히려 최선인 경우가 많다.

**세금 부작용은 남는다** — 국내상장 해외 ETF의 해지상환은 매매차익이 **배당소득**으로 과세되므로 [02 §5.2](02-investment-engine.md)의 금소세·건보 누적기에 직접 반영되며, **우리가 선택하지 않은 타이밍에 과세소득이 발생**한다. 이것이 `ESC_REPLACE`(사전 이동)가 승인 경로로 존재하는 두 가지 정당한 사유 중 하나다.

### 7.5 업비트 유의종목 지정의 가격 반응 — 등급: 확인(공개 시세 기록)

**2021-06-11, 25개 종목 17:30 일괄 유의종목 지정** 당일 하락률:

| 종목 | 당일 |
|---|---|
| LBRY | **−43.25%** |
| 람다 | −27.29% |
| NXT | −25.42% |
| (25종 전반) | −10 ~ −43% |

**가격 반응이 공지와 사실상 동시에 일어난다.** 따라서 "감지 후 자동 매도"는 손실 회피가 아니라 **최악의 가격에 파는 것을 자동화**하는 것이다. [06 §10](06-realtime-and-surveillance.md)이 "감지 즉시 자동 청산을 넣지 않는 결정은 영구적"이라고 못 박은 1차 근거다.

### 7.6 미국 소스 — 등급: 중 / 일부 재확인 필요

- KIS 해외 `search_info`의 거래정지·상폐 필드는 코드에 존재(확인). **갱신 지연은 미확인**.
- **LULD pause 실시간 추적은 영구 제외**([00 §6.2](00-overview.md)) — 미국 기본 경로가 LOC(종가 체결)라 장중 halt 노출이 구조적으로 작다.
- **미국 ETF 청산(liquidation) 발표는 무료 체계적 소스가 없다**(발행사 보도자료뿐). [06 §9.4](06-realtime-and-surveillance.md)의 잔여 미탐 리스크로 등재. 부재 증명이므로 등급은 **중**.

## 8. KIS·업비트 API 실시간 최대 활용 (R-B) — [06 §1·§3](06-realtime-and-surveillance.md)의 근거

### 8.1 확정된 제약 — 등급: 확인(공식 문서·공식 샘플 코드)

| 항목 | 값 |
|---|---|
| KIS REST 유량 | 실전 **20 rps** / 모의 **2 rps** (안전예산 15로 운용) |
| KIS 접근토큰 | 유효 24h, **1분 1회 재발급 제한**(`EGW00133`) |
| KIS WebSocket 등록 상한 | **41건** — (`tr_id` × `tr_key`) 쌍 단위, **국내·해외·체결통보 전부 단일 세션 공용 예산** |
| 공식 샘플의 실제 캡 | **40**에서 하드 캡 |
| 체결통보 암호화 | AES256-CBC |
| 멀티시세 | `intstock-multprice` **1콜 = 30종목** |
| 업비트 REST | 주문 8/s·200/min, 주문취소 30/s·900/min, Quotation 10/s·600/min |
| 업비트 WS | 5/s·100/min, `remaining-req` 헤더, **120초 Idle Timeout** |
| 업비트 API 키 | **1년 만료** |

### 8.2 "최대 활용"의 산술 — 왜 헤드룸이 남는가 — 등급: 확인(산술) + 추정(평시 소비)

[R2]의 문언은 "한도 내 최대 활용"이지만, **소비할 이유가 구조적으로 없다.**

```
보유∪후보 ~20종목의 시세 스냅 1회 = ceil(20/30) = 1콜        (30종목/콜)
평시 비집행 시간대: 60초마다 시세 1콜 + 잔고 1콜 = 0.033 rps
감시 서브시스템 하루 총 KIS REST 소비 ≈ 45콜 = 15 rps 예산의 3초 분량
```

| 상태 | 추정 평시 소비 | 안전예산(15 rps) 대비 |
|---|---|---|
| WS 도입 **전** | 약 0.8 rps | 5.3% |
| WS 도입 **후** | 약 **0.25 rps** | **1.7%** |

**실시간 도입이 한도 압박을 늘린다는 직관은 틀렸다** — 체결확인 폴링과 업비트 ticker 폴링이 WS로 대체되면서 REST 소비가 **줄어든다**. 이것이 T0 채널을 게이트 없이 채택한 이유 중 하나다.

**헤드룸의 실제 용도는 비정상 국면의 버스트 용량**이다(재시작 catch-up / P8 자가치유 3회 재조회 / WS 전면 폴백 / 카세트 스모크). 정상 운용에서는 실제로 아무것도 하지 않는다 — [06 §3.3](06-realtime-and-surveillance.md)이 이것을 "최대 활용의 대체 서사가 아니다"라고 명시한 이유.

### 8.3 41건 예산이 사다리를 필요로 하지 않는 이유 — 등급: 확인(산술)

```
고정            : H0STCNI0 1 + H0GSCNI0 1                   =  2
활성 종목당 4건 : ASP0 + MKO0 + CNT0 + NAV0                 =  4n
n=9 → 2 + 36 = 38 = 운용 상한 (하드 41, 예비 3)
```

동시 구독 대상은 "당일 계획 전 종목"이 아니라 **현재 활성 주문 ∪ 다음 슬라이스 후보**(통상 2~5)다. [02 §4.3](02-investment-engine.md)이 "매도 먼저, 체결 확인 후 매수"를 규정하므로 실제 동시 활성은 더 작다. KRX(≤15:40)와 US(≥22:30) 세션은 KST 상 겹치지 않아 36건을 통째로 재사용한다.

**따라서 예산의 60~70%만 쓰는 상태에서 3단 축약 사다리·LRU 강등·우선순위 스코어링은 순수한 과잉설계다** → 어서션 2줄로 충분하다([06 §1.3](06-realtime-and-surveillance.md)).

### 8.4 재확인 필요 항목 — 등급: **재확인 필요**

`H0STMKO0` 구독의 41건 소모 단위 / 체결통보가 예산에 포함되는지 / 구독 해제 `tr_type` 값 체계 / `wss://` 지원 여부. **이들만 M9 착수 시에만 수행**하며 M9가 취소되면 검증하지 않는다([06 §13.2](06-realtime-and-surveillance.md)). **`approval_key` 유효기간·앱키당 세션 수(SP-B3)는 T0가 의존하므로 M1 W7**, **`HDFSCNT0` 실지연은 M6**로 분리했다([04 §5.2](04-roadmap.md)).

## 9. 완전 자동화의 구조적 갭 (R-C) — [00 §3](00-overview.md) 자동화 등급표의 근거

### 9.1 자동화를 막는 것은 기술이 아니다 — 등급: 높음

[R1]("계좌 연동 외에는 조작 없이")을 가로막는 장벽을 전수 조사한 결과, **기술적으로 불가능한 것은 하나도 없었다.** 남는 강제 개입은 전부 아래 네 범주다.

| 범주 | 항목 | 왜 자동화되지 않는가 |
|---|---|---|
| **대리권** | 양도세 대행신고 신청(T5) | **위임 계약 체결**이며 본인의 의사표시다. API 부재 여부와 무관하게 대리권 근거가 남는다 |
| **사업자 미제공** | KIS 앱키·업비트 키 로테이션(O1) | **두 사업자 모두 갱신 API가 없다.** KIS는 만료 30일 전부터만 갱신 버튼이 열리고, 갱신 시 키가 **재발급**되어 구 키가 무효화된다 |
| **의도적 금지** | 배포·의존성 업데이트(O2), 세법 개정 반영(T7), 코드 변경 | 자동화 불가가 아니라 **자동화 금지**. 돈을 다루는 프로세스에서 사람이 읽지 않은 코드가 배포되는 경로를 만들지 않는다 |
| **고가치 개입** | 공제 한도 잔여 이체(T9) | §9.3 — 자동화하지 않는 것이 **의도적으로 옳다** |

### 9.2 API 키 로테이션이 무인 운용의 최대 단일 실패점 — 등급: 높음

**업비트 API 키는 1년 만료이고, KIS 앱키도 갱신이 필요하다. 둘 다 자동 갱신 경로가 없다.** 부재 중 만료가 발생하면 시스템은 조용히 인증 실패 상태가 되고, 그것이 P9(연속 오류)를 통해 HALT로 이어진다.

완화책 셋([01 §6.2](01-architecture.md), [03 §5.3.4](03-safety-operations.md)):

1. **발급일을 6개월 이상 분산** — 두 키가 동시에 만료되지 않게.
2. **D-45 ~ D-1 알림 사다리** + 부재 기간과 겹칠 경우 사전 경고.
3. **D-7 슬리브 `PAUSED_ALL`(양방향 정지) / D-3 전체 `SAFE_MODE` 자동 조치** — 알림을 못 봤을 때의 최종 방어. `PAUSED`(신규 매수만 중단)로는 매도·정정·취소가 계속 실패해 P9-order를 유발하므로 방어가 성립하지 않는다(03 §2.1).

**시크릿 만료 대장이 1급 운영 항목인 이유가 이것이다.** 코드 품질과 무관하게 이 하나로 시스템이 죽는다.

### 9.3 강제 개입 0회를 추구하면 손해다 — 등급: **확인(세법) + 산술**

[00 §2.2-④](00-overview.md)("강제 개입 최소화 ≠ 개입 0회")의 정량 근거.

```
세액공제 한도 = 900만원 (연금저축 600 + IRP 300)
공제율        = 13.2% (총급여 5,500만 초과) ~ 16.5% (5,500만 이하)

연금저축 600만 미소진   = 600만 × 13.2~16.5% =  79.2만 ~  99.0만원   ← 문서 전반이 인용하는 수치
IRP 300만 미소진        = 300만 × 13.2~16.5% =  39.6만 ~  49.5만원
900만 전액 미소진       = 900만 × 13.2~16.5% = 118.8만 ~ 148.5만원

시스템 전체 추정 알파   ≈ 연 5 ~ 21bp  (§4.5.1에서 차용한 값)
```

문서 전반의 "79~99만원"은 **연금저축 600만원 한도만 미소진한 경우**의 값이며, 가장 보수적인 축(세 시나리오 중 최소)을 인용한 것이다.

**NAV 1억 기준으로 시스템 알파는 연 5~21만원인데, 공제 한도 미소진 1회는 79~99만원이다.** 한 번의 미소진이 시스템 알파의 **4~20년치**를 지운다.

**따라서 `waterfall_gap_check`(11/1)는 "자동화하지 못한 잔여"가 아니라 의도적으로 추가한 강제 개입이다**([02 §1.3.2](02-investment-engine.md), [00 §3.2](00-overview.md) T9). 감지·계산·알림은 A0로 자동화하고, **이체 행위만 사람에게 남긴다** — 이체 자동화의 실패 모드(한도 초과 납입, 계좌 오지정)가 절세액을 상회할 수 있기 때문이다.

> **이 절이 [R1]에 대한 우리 답의 핵심이다.** [R1]을 문언 그대로 추구하면 연 79~99만원을 버리게 된다. [00 §2.2](00-overview.md)의 판정 규칙("수익 개선에 최대한 도움되는 방향")이 적용되어, **개입을 늘리는 방향으로 설계했다.**

### 9.4 절세계좌 자동화의 미확인 지점 — 등급: **재확인 필요 (SP-C4)**

[00 §3.3](00-overview.md)의 "연 3~6회 / 40~60분"은 **SP-C4(절세계좌 API 주문 지원 여부)가 성공한 경우의 값**이다. 실패하면 ISA/연금/IRP가 지시서 모드가 되어 연 1~2회 이행 조작이 추가되고, 그것은 명백히 "앱 조작"이므로 **[R1]은 "충족"이 아니라 "거의 달성"이 된다.** SP-C4를 M1 최우선 배치 스파이크로 둔 이유다.

### 9.5 세무 자동화의 한계선 — 등급: 높음

## 10. 자가 개선과 최신 알고리즘 동향 (R-D) — [07](07-self-improvement.md)·[02 §3.6](02-investment-engine.md)의 근거

### 10.1 우리 문제의 차원이 최신 문헌 대부분을 무효화한다 — 등급: 확인(학술 원문 + 산술)

```
유니버스  N ≈ 8~12
룩백      n = 756 (3년 일간)
집중비율  c = N/n ≈ 0.011 ~ 0.016
```

2015년 이후 공분산·배분 문헌의 주류는 `c → 1`(개별주 수백~수천 종목)을 푸는 **고차원 처방**이다. 표준 점근 영역(`c → 0`)에서는 **최적 shrinkage 강도가 `c`의 감소함수로 0에 수렴**한다.

**우리는 그 병에 걸리지 않았다.** 이것이 [07 §4.4](07-self-improvement.md)의 하드 거부 규칙 HR-1의 근거이며, 아래 판정들이 전부 여기서 나온다.

| 기법 | 판정 | 이 절에서의 근거 |
|---|---|---|
| Nonlinear shrinkage (QIS/GIS) | 거부 | 고차원 처방. skfolio에 없어 자체 구현 비용까지 발생 |
| Denoising (RMT) | 거부 | `c`가 작으면 **노이즈 고유값 대역이 거의 빈다** |
| **Detoning (RMT)** | **금지** | 첫 고유벡터(시장 요인)를 제거하는데, **글로벌 자산배분에서 시장 요인은 배분 대상 그 자체**다. 종목 선택 도구를 배분에 쓰는 것 |
| NCO | 거부 | 고차원 처방 |
| HERC | 거부 | HRP의 역할은 성능이 아니라 **독립 2차 의견**. 같은 계열이라 독립성만 떨어진다 |
| Entropy Pooling | 거부 + 훅 | BL의 엄밀한 일반화이나 **견해 0개면 posterior = prior**. 지금 교체해도 산출물이 한 비트도 안 바뀐다 |
| **Schur Complementary** (Cotton 2024) | **M2 진단 실험** | HRP와 최소분산이 하나의 연속 스펙트럼임을 보인 신개념. **배분기 교체가 아니라 [02 §3.4](02-investment-engine.md) 임의 임계(20%p)의 정량화 용도** — 논문에 없는 우리 자체 응용이므로 등급 **추측** |

### 10.2 꼬리 위험 목적함수의 표본 문제 — 등급: 확인(산술)

```
756 관측치 × 5% = 38개 관측치가 5%-CVaR 전체를 결정한다
```

8~12자산의 배분을 38개 관측치로 정하는 것은 **raw MVO보다 나쁜 추정오차 증폭**이다(§4.2의 MVO 비판이 그대로, 더 강하게 적용된다). CDaR·드로다운 제약은 더 심하다 — **드로다운은 경로 의존적이라 표본이 실현 경로 1개뿐**이다.

→ 목적함수로는 거부, **리포팅 지표로는 채택**(비용 거의 0, 정보 가치 있음). [07 §4.4](07-self-improvement.md) HR-6.

### 10.3 백테스트 숫자는 그 자체로 증거가 아니다 — 등급: 높음

**Implementation Risk (arXiv 2603.20319, 2026-03)**: 15개 전략을 5개 독립 백테스트 엔진에 통과시킨 결과 —

- **거래비용 0에서는 모든 엔진이 일치한다.**
- **비용이 0이 아닌 순간 결론이 갈린다.** 발산은 전적으로 비용 모델 차이에 기인.

함의 셋:

1. 외부 백테스트 숫자는 그 자체로 증거가 아니다 → §0의 등급 규칙이 "성능 주장"에 특히 엄격해야 하는 이유.
2. **"거래비용 0 백테스트"는 자동 거부 사유로 코드화 가능** → [07 §4.4](07-self-improvement.md) HR-2.
3. [02 §8.1](02-investment-engine.md)의 상세 비용 모델과 [03 §4.6](03-safety-operations.md)의 TE 5항목 분해가 **우리 쪽 강점**이다.

### 10.4 ML 자산배분 — 거부 근거의 정확한 표현 — 등급: 높음

**"ML은 실패한다"는 반증 가능한 과장이므로 쓰지 않는다.** 정확한 서술:

> 우리 문제는 자유도가 낮고(`N≈10`, 월 1회 재추정) 표본이 짧아, **ML이 이기는 조건(고차원 · 대량 표본 · 저비용 집행)을 하나도 갖추지 못했다.**

보강 근거 둘:

- **Harvey et al. (JPM 2018)**: 변동성 타게팅이 주식·크레딧에서 Sharpe를 개선하나 **채권·통화·원자재에서는 무의미**. 코어는 주식+채권 혼합이므로 절반이 무효.
- **Cederburg·O'Doherty·Wang·Yan (JFE 2020, 103개 전략)**: spanning regression의 양(+) alpha가 **실시간 구현 불가능**하며, 합리적 out-of-sample 버전은 unmanaged 대비 **낮은 certainty equivalent와 낮은 Sharpe**를 낸다.

**크립토 슬리브의 vol targeting만 유지**한다. 근거 강도는 "강함"이 아니라 **"중간 + 이론적 방향성 일치"**로 표기한다(지지 자료 상당수가 동료심사 저널이 아니다).

> **인용을 뒤집지 않는다.** "주 1회 갱신이 Cederburg의 실시간 구현 불가 비판을 회피한다"는 서술은 **논문 결과의 역방향 사용**이다 — Cederburg가 보인 것은 "실시간으로 구현 가능한 버전은 unmanaged보다 열위"이지 "갱신을 드물게 하면 유효해진다"가 아니다. **정확한 서술**: Cederburg의 결과는 이 규칙에 **부정적**이다. 그럼에도 유지하는 근거는 ① Harvey et al.(JPM 2018)의 risk asset(주식·크레딧) 개선 결과가 크립토에 준용된다는 판단 ② **슬리브 기본 3%·상한 10%로 오류의 손실 상한이 봉인**되어 있다는 구조적 사실이며, 근거 강도는 **"중간"**이다. 검증은 [02 §8.2](02-investment-engine.md) EX-4에 **"unmanaged(스케일링 없음) 대비 세후 Sharpe"** 판정 지표를 추가해 수행한다.

### 10.5 성과 기반 자동 판정이 불가능한 이유 — 등급: 확인(산술) + 추정(σ_d)

[07 §10.2](07-self-improvement.md)의 근거.

```
챔피언·챌린저 차이 수익률의 표준편차 σ_d ≈ 연 1.5%   ← 추정 (밴드·쿨다운 수준의 파라미터 차이)
진짜 차이 μ_d = 연 20bp 가정
t = 2 에 필요한 기간 T = (2·σ_d / μ_d)² = (2×1.5/0.2)² = 225년
```

**σ_d가 절반(0.75%)이어도 56년이다.** 결론(60~90일 표본으로 우열 판정 불가)은 σ_d 추정의 정확도에 의존하지 않는다.

→ 롤백 트리거를 성과가 아니라 **프로세스 지표**(잔차·가드 발동·회전율·집행 실패율·불변식 위반)로 정의한 근거. 성과 기반 롤백은 **롤백 진동**과 **최근 국면 추종**(자동화된 마켓타이밍)을 만든다.

### 10.6 자가 개선 시스템 자체의 실패 모드 — 등급: 중(업계 관측 + 추론)

| 실패 모드 | 우리 방어 |
