# S03-1 Core States Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계 02 §9의 전역·슬리브·부재 상태와 제약 축을 정확한 enum 및 불변 Pydantic 값 객체로 구현해, 이후 보호 계층이 문자열·정수 관례를 재정의하지 않고 하나의 타입 계약을 사용하게 한다.

**Architecture:** `core.states`는 상태·축·제약 벡터의 타입과 값만 소유한다. `protections`가 소유하는 상태별 벡터 표, 결합 함수, 전이, SAFE_MODE 사유 refcount는 이번 모듈에 두지 않는다. `None` net-buy cap은 무제한 항등 표현이며 Pydantic의 JSON 직렬화·역직렬화에서 손실 없이 보존한다.

**Tech Stack:** Python 3.12 표준 라이브러리(`enum`, `decimal`), Pydantic v2, pytest, ruff, mypy, import-linter.

## Global Constraints

- `docs/design/02-domain-model.md` §9 [DD-02-13]이 구현 정본이다.
- 구현 범위는 `docs/design/17-implementation-progress.md`의 S03-1 하나다.
- `BotState`·`SleeveState`·`PresenceState`의 이름과 문자열 값은 설계 스케치와 문자 단위로 일치해야 한다.
- `BuyAxis`와 `SellAxis`는 `IntEnum`이며 작은 정수가 더 제한적이다.
- `NetBuyCap`과 `ConstraintVector`는 `BaseModel, frozen=True`인 값 객체다.
- Decimal 필드는 기존 `omra.core.money.Dec`를 재사용해 float·bool 유입을 차단한다.
- 설계에 없는 양수 범위나 SAFE_MODE 기본 수치를 추정해 검증기로 추가하지 않는다. 값 정책은 config·protections 계층이 소유한다.
- `IDENTITY`, `combine`, `min_cap`, 상태별 벡터 표, 상태 전이, `StateView`, SAFE_MODE 사유 관리는 추가하지 않는다.
- 상태 전용 직렬화 API를 새로 만들지 않고 Pydantic v2 표준 `model_dump(mode="json")`·`model_validate_json()`을 사용한다.
- `omra.core.__init__` 재수출과 새 의존성을 추가하지 않는다.
- 최종 커밋은 공식 Codex 구현과 GitHub 규약에 맞춰 `Co-authored-by: Codex <noreply@openai.com>` 트레일러를 정확히 한 번 사용한다.
