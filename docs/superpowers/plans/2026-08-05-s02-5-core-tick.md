# S02-5 Core Tick Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 설계 02 §6의 호가단위 산술을 `Decimal` 전용 순수 함수로 구현해 주문 가격을 보수 방향으로 정규화하고, 미확정 거래소 규칙은 추정 없이 fail-closed로 차단한다.

**Architecture:** `core.tick`이 규칙 식별자, 확정 균일 호가단위, 향후 사다리 표 자리, 스냅·재호가·틱 거리 산술의 유일한 소유자다. 공개 함수는 `(price, ..., rule)` 인자 순서를 유지한다. 확정되지 않은 `krx7`·`upbit` 표는 빈 버전 상수와 strict xfail 경계 스캐폴드만 두며 런타임에서는 `TickRuleError`를 발생시킨다.

**Tech Stack:** Python 3.12 표준 라이브러리(`decimal`, `enum`, `typing`), pytest, Hypothesis, ruff, mypy, import-linter.

## Global Constraints

- `docs/design/02-domain-model.md` §6 [DD-02-7·8]이 구현 정본이다.
- 구현 범위는 `docs/design/17-implementation-progress.md`의 S02-5 하나다.
- `TickRuleId` 값은 `krx_etf_5`, `krx7`, `usd_penny`, `upbit` 네 문자열과 정확히 일치해야 한다.
- 이번 단위에서 활성화하는 규칙은 확정된 `krx_etf_5=5`와 `usd_penny=0.01`뿐이다.
- `usd_penny`는 모든 가격 입력과 산출에서 `1 USD` 미만을 거부한다.
- `krx7`·`upbit`의 경계·호가단위를 외부 지식이나 관행으로 추정하지 않는다.
- 모든 가격은 실제 `Decimal`, finite, 양수여야 한다. `float`, `bool`, `int`, NaN, Infinity는 `TickRuleError`다.
- 스냅 결과가 0 이하가 되면 주문 가격으로 사용할 수 없으므로 `TickRuleError`다.
- `snap_buy`는 내림, `snap_sell`은 올림이며 결과의 Decimal quantum은 해당 틱과 일치한다.
- 사다리 하한은 inclusive다. `next_up`은 다음 하한을 과점프하지 않고, 경계에서 `next_down`은 이전 구간 틱을 사용한다.
- `ticks_between`은 비격자 끝점을 거부하고 `lo > hi`만 `InvariantViolation`으로 구분한다.
- 새 의존성, 설정 파일 호가표, 실행 정책, S03-7 AST 규칙을 추가하지 않는다.

### Task 2: Implement the production tick arithmetic

**Files:**
- Create: `src/omra/core/tick.py`

- [x] **Step 1: Define identifiers and versioned tables**

- define the exact `TickRuleId(StrEnum)` contract;
- store confirmed uniform ticks as `Decimal` constants;
- define typed, empty `_KRX7_LADDER` and `_UPBIT_LADDER` constants with `[확인 필요]`, source, and future activation stage comments;
- dispatch unknown or empty rules to `TickRuleError`.

- [x] **Step 2: Centralize validation and segment lookup**

- validate exact `Decimal`, finiteness, positivity, rule type, and USD minimum;
- validate ladder structure before arithmetic so a future malformed table cannot silently price orders;
- select the last inclusive lower bound and retain the next boundary for crossing logic.

- [x] **Step 3: Implement snapping and one-tick movement**

- implement uniform and ladder floor/ceiling relative to each segment lower bound;
- preserve tick quantum through `Decimal.quantize`;
- reject non-positive or out-of-domain results;
- clamp upward movement to the next lower bound when one current-tier tick would cross it;
- at an exact noninitial boundary, move downward with the previous tier tick.

- [x] **Step 4: Implement alignment and bounded-complexity distance**

- define alignment by equality to `snap_buy` after validation;
- reject unaligned `ticks_between` endpoints;
- use direct division for uniform rules;
- count ladder segments rather than iterating once per price tick, including one clamped transition when a boundary is not reachable by the previous tier quantum.
